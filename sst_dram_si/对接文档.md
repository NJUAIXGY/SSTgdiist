# DRAM-SI/GAS 当前实现对接文档（供审阅）

本文件汇总目前在 DRAM-SI 路径下已落地的两种访存方案（方案1基线、方案2 GAS）的实现要点、参数接口、构建运行方法、统计口径与自检工具，便于评审与对接。

---

## 1. 总览与范围

- 目标：在单PE内（无网络）基于 memHierarchy + Ramulator2 验证两种访存方式，并提供可控的合并/排序/窗口化基础设施与稳定的统计输出。
- 两种方案：
  - 方案1（基线）：每个 superstep 仅处理 DRAM 权重的 1/8 切片（按列块分片），其余 spike 延后至后续 superstep；不做按需精确加载优化，保留“行×列段（CL）”的粗粒度扫描（作为对比基线）。
  - 方案2（GAS）：引入 Gather→Apply→Scatter 三阶段，Gather 阶段收集并去重/合并读，Apply 阶段统一发起并响应，Scatter 阶段更新/发放；支持细粒度合并（gap≤k、Lmax）与行窗口合并（按 bank,row 的 bytes/timeout 触发）。
- 基础设施：
  - 前端：`SnnDL.GatherBufferIF`（GAS 专用 StandardMem 前端 + SRAM scratchpad）
  - 内核：`SnnDL.SnnPESubComponent`（方案1状态机、GAS集成）
  - 聚合：`SnnDL.MultiCorePE`（统计聚合、窗口化统计）
  - 后端：`memHierarchy.Cache/L2/MemController + ramulator2Backend`

目录与脚本：
- 主脚本：`sst_dram_si/test_dram_si_single_pe.py`
- 本地配置：`sst_dram_si/local_run_config.json`
- 统计目录：`sst_dram_si/stats/`（CSV）、`sst_dram_si/logs/`（stdout 摘要）
- DRAM 配置：
  - DDR4（OpenRow，支持 bank_row 对齐）：`sst_dram_si/configs/ramulator2_ddr4_openrow.cfg`
  - HBM2（含 RandomTranslation，bank_row 自动退化为 row）：`sst_dram_si/configs/ramulator2_hbm2.cfg`
- 自检工具：
  - 细合并与分桶：`sst_dram_si/tools/selfcheck_gap_merge.py`
  - 行窗口（bytes/timeout）：`sst_dram_si/tools/selfcheck_row_window.py`

## 2. 组件与职责（关键文件）

- `SnnDL.GatherBufferIF`：GAS 的内存前端，负责：

  - 支持 SRAM scratchpad（LRU逐段缓存）；
  - 细合并（gap≤k 与 Lmax）和行窗口合并（bytes/timeout 按 bank,row 分桶）；
  - 统计：`gas_unique_reads/bytes`、`gas_gap_absorbed_bytes`、`gas_row_window_*`、阶段时长等。

  - 方案1（基线）状态机：跨 superstep 的块轮换（每次只处理一个切片，其余 spike 延后到对应轮次），保留粗粒度扫描预取（不做按需精确加载）。

## 3. 方案1（基线）实现

- 语义：
  - superstep 级块轮换：一次只处理 DRAM 权重空间的 1/8 切片；当期不属于该切片的 spike 入延后队列，等轮换到对应块再处理。
  - 预取策略：保留“行×该 slice 列段”的 cacheline 步进扫描，会读取很多未触发数据（刻意不优化，作为基线对比）。
- 关键代码：
  - 块轮换/延后队列：`SnnPESubComponent.cc`（方案1状态机，参考 `scheme1Tick_()`、`scheme1Reset_()` 路径）
  - 粗粒度扫描预取：`SnnPESubComponent.cc:1539` 附近（行循环 + 列段CL步进 + 发读）
- 统计口径：
  - 读字节：从父组件 `multicore_pe_0,mem_req_size_bytes.Sum.u64` 汇总（CSV）
  - 事务/行命中/平均延迟：从 ramulator2 stdout 摘要提取

## 4. 方案2（GAS）实现

### 4.1 阶段与窗口

- 阶段：Gather → Apply → Scatter；默认使用 window 驱动（`window_auto=1`）
  - Gather：收集上游 Read，不立即处理；统计 `gas_upstream_reads`；可延后到 Apply 再统一下发
  - Apply：统一排序/合并并发起下行 Read；等待数据就绪后，从 SRAM 回应上游
  - Scatter：（可选）完成后 `flush_after_scatter=1` 时清空 SRAM
- 集成（上层）：当 `gas_window_mode=1` 时，SnnPESubComponent 不再每周期发送 Begin/EndGather，由 GatherBufferIF 自身的时钟与窗口参数推进（`window_cycles_*`）。

### 4.2 合并与排序

- 细粒度合并（gap/Lmax）
  - 原理：若两段之间空洞 gap ≤ k 且新段长度 new_len ≤ Lmax，则吸收空洞合并为一次突发；k 的物理含义为 `(tRA+tCA+tPRE)*B` 的等效空洞字节。
  - 参数：`gap_merge_enable`、`gap_merge_k_bytes`（k）、`burst_bytes_max`（Lmax）
  - 统计：`gas_gap_absorbed_bytes`（吸收的空洞字节总量，Accumulator）；`gas_req_coalesce_size_bytes`（合并后突发长度分布，Histogram）

- 粗粒度合并（行窗口，默认关闭；已落地）
  - 分桶：按 `(bank,row)`（当 `bank_bits=0` 时退化为仅 row）
  - 触发（二选一或同时生效）：
    1) bytes 阈值：若当前段内子读字节和 `seg_sum_bytes+size ≤ row_window_bytes` 且 `new_len ≤ burst_bytes_max`，允许跨大 gap 合并（标记为 row-window 合并）；
    2) timeout 阈值：若首个子读到达与新读到达时间差 `≥ row_window_timeout_ns`，先封口为一次 row-window 突发，再开新段；
  - 参数：`row_window_enable`、`row_window_bytes`、`row_window_timeout_ns`（默认均为 0/关闭）
  - 统计：`gas_row_window_triggers`（触发次数）、`gas_row_window_bytes`（该类突发覆盖字节，含空洞；Accumulator）

- 排序策略：`sort_policy=addr|row|bank_row`（默认 row）。当选择 `bank_row` 时支持自动对齐：`bank_bits/bank_shift` 设为 "auto"（或留空）即可由内核启发式推断；若无法可靠推断或 cfg 启用 `RandomTranslation`，将自动降级为 `row` 并打印提示。

### 4.3 SRAM scratchpad

- 容量：`sram_bytes`；LRU 淘汰：`ensureCapacity_()`
- 行为：下行 Read 回来后放入 `sram_blocks_`，Apply 阶段从 SRAM 构造 ReadResp 返回上游
- 统计：`gas_evictions`（淘汰次数）、`gas_buffer_occupancy_bytes`（SRAM 占用采样）

### 4.4 已落统计（ELI 注册，CSV 可见）

- `gas_unique_reads`、`gas_unique_bytes`、`gas_upstream_reads`、`gas_evictions`、`gas_inflight_peak`、`gas_tail_wait_ns`
- `gas_stage_cycles_gather|apply|scatter`（窗口模式阶段时长）
- `gas_req_coalesce_size_bytes`、`gas_buffer_occupancy_bytes`（Histogram）
- `gas_gap_absorbed_bytes`、`gas_row_window_triggers`、`gas_row_window_bytes`

代码参考：
- GatherBufferIF 统计注册：`SnnDL/GatherBufferIF.cc:71`（`registerStatistic`…）
- 行窗口合并与统计：`SnnDL/GatherBufferIF.cc:380`（flush_segment 统计）、`:418`（timeout 触发）、`:428`（bytes 触发）
- 上行字节/事务聚合：`SnnDL/GatherBufferIF.cc:153, 244`（下行返回时统计并上报到上层）

## 4+. 方案2（GAS）实现细节（逐点展开）

本节对 GAS 的控制面、数据面、合并算法、窗口控制、SRAM 管理、统计与上层对接逐项说明，并给出与源码的对应锚点，便于审阅。

- 关键词总览（参数 → 行为）
  - `window_auto`/`window_cycles_*`：由 GatherBufferIF 自驱动 GAS 三阶段（替代上层逐周期 Begin/End）
  - `defer_issue_until_apply`：Gather 阶段仅收集；Apply 入口统一“构建→排序→下发”（默认 0；建议 `window_auto=1` 时启用=1；`window_auto=0` 时 Apply 阶段读会强制即时下发以避免死锁）
  - `gap_merge_enable` + `gap_merge_k_bytes`(k) + `burst_bytes_max`(Lmax)：细粒度 gap/Lmax 合并
  - `row_window_enable` + `row_window_bytes` + `row_window_timeout_ns`：行窗口（粗粒度）按 bytes/timeout 触发
  - `sort_policy=row|bank_row|addr` + `bank_bits/bank_shift`：排序/分桶键
  - `sram_bytes` + LRU：SRAM scratchpad 容量与淘汰
  - `strict_mode`：非 Gather 阶段的读请求是否缓存到下一窗口

1) 控制面与阶段转换（window 模式）
  - 初始化：`init()` 在 `window_auto=1` 时注册自己的时钟，设置 `stage_=Gather` 并递增 `current_gather_id_`（GatherBufferIF.cc:96-117）
  - 时钟回调：`clockTick()` 维护 `stage_counter_`，当 `stage_counter_>=window_cycles_gather` 自动置位 `end_gather_seen_` 并调用 `maybeEnterApply_()`；Apply/Scatter 窗口类似（GatherBufferIF.cc:520-560）
  - 统计：阶段时长以周期计入 `gas_stage_cycles_*`（Histogram）

2) 上游请求接入（Gather 阶段的数据面）
  - 接收：`send()` 中判定 `if (auto* rd = dynamic_cast<Read*>(req))` 且 `stage_==Gather/Apply`（Apply 阶段读也属于“当前窗口”，避免错落到下一窗）
  - 延后：当 `defer_issue_until_apply=1` 且启用 gap/Lmax 路径时，把上游 Read 暂存到 `staging_reads_`，并记录到达时间 `staged_arrival_ns_[id]=now_ns`（GatherBufferIF.cc:159-164；头文件字段：GatherBufferIF.h:163-165）
  - 注意：Apply 阶段的 staging 仅在 `window_auto=1` 时支持（依赖 `clockTick()` drain）；当 `window_auto=0` 时，Apply 读会强制走即时构建/下发以保证 forward progress。
  - 非延后（回退路径）：若 `defer_issue_until_apply=0`，则按 `merge_policy` 立即构建静态 granule（整行或CL），并可立刻 issue（GatherBufferIF.cc:165-178）
  - 严格模式：若非 Gather 阶段且 `strict_mode=1`，则把上游 Read 缓存到 `queued_non_gather_reads_`，待下一窗口吸纳（GatherBufferIF.cc:181-189, 552-571）

3) Apply 入口的构建/合并/排序（延后模式主路径）
  - 触发：`maybeEnterApply_()` 在见到 EndGather 时进入 Apply；若 `defer_issue_until_apply=1`，首先调用 `buildGranulesWithGapMerge_()`（GatherBufferIF.cc:307-350）
  - 分桶键：`(bank,row)`；当 `bank_bits=0` 时退化为 `row`；计算方式见 `bankIndex()/rowIndex()`（GatherBufferIF.h:128-131；构建分组：GatherBufferIF.cc:361-368）
  - 组内排序：按地址升序（GatherBufferIF.cc:368, 373）
  - 细合并（gap/Lmax）：若 `gap<=k` 且 `new_len<=Lmax`，则吸收空洞（`gap_absorbed_bytes` 累加），合并到当前段（GatherBufferIF.cc:414-417）
  - 行窗口（bytes 阈值）：若 `seg_sum_bytes+size<=row_window_bytes` 且 `new_len<=Lmax`，允许跨大 gap 合并，标记 `seg_used_row_window=true`（GatherBufferIF.cc:428-433）
  - 行窗口（timeout 阈值）：若 `it.arr_ns - seg_start_ns >= row_window_timeout_ns`，先将现段封口并标记“行窗口触发”，再以当前读开新段（GatherBufferIF.cc:418-426）
  - 封口与统计：`flush_segment(mark_rowwin)` 将段转为 granule，并在 `seg_used_row_window || mark_rowwin` 时递增 `gas_row_window_triggers` 与 `gas_row_window_bytes+=段覆盖字节`（GatherBufferIF.cc:380-399, 390-396, 441-444）
  - granule key：`(base<<32)^(size)`；必要时在首次插入时把 `(base,size)` 记入 `granules_[key]` 并将 `key` 加入 `required_set_`（GatherBufferIF.cc:382-388）
  - 排序与下发：构建完成后对 granules 生成排序键（`addr|row|bank_row`），按策略排序并逐个 `issueGranule_()`，受 `max_inflight_reads_` 限制（GatherBufferIF.cc:320-334, 234-241）

4) 下行响应与 SRAM 回填
  - 回调：`onDownstreamResp_()` 匹配 `inflight_down_` 找到 granule key，以 `ensureCapacity_()` 保证容量后写入 `sram_blocks_[key]`，并置 `ready=true`（GatherBufferIF.cc:244-267, 472-479）
  - LRU 淘汰：`ensureCapacity_()` 当不足时按 `lru_list_`（front→oldest）逐段淘汰，并计 `gas_evictions`（GatherBufferIF.cc:466-472）
  - 统计与上卷：每个 granule 返回时累加 `gas_unique_reads`、`gas_unique_bytes+=g.size`；并发送 `CustomResp(GasStatData{1, g.size})` 到上层 PE 聚合（GatherBufferIF.cc:258-268；数据载体：GasCustomCmd.h:61-83）

5) Apply 阶段上行响应生成
  - 条件：当 `required_set_` 中所有 granule `ready` 时，或 `window_cycles_apply` 到达时（窗口模式），调用 `emitApplyResponses_()`（GatherBufferIF.cc:288-309, 332-343, 558-565）
  - 行为：对每个 granule 的 `subs`（上游子读），以 `offset/size` 从 `sram_blocks_[key]` 取出字节，组装 `ReadResp` 发回上游，并删除对应 `pending_up_reads_`（GatherBufferIF.cc:450-469）
  - 清理：Apply 发放后清空 `granules_/required_set_/staging_reads_`，`end_gather_seen_=false`（GatherBufferIF.cc:470-475, 445-448）

6) Scatter 阶段与 flush
  - 行为：若 `flush_after_scatter=1`，在 Scatter 结束或阶段切换时 `doFlush_()` 清空 SRAM 缓存（GatherBufferIF.cc:140-149, 476-479, 559-567）

7) 关键参数的语义与边界
  - k（gap_merge_k_bytes）：吸收空洞的阈值，工程近似 `k ≈ (tRA+tCA+tPRE)*B`（单位字节），按 DRAM 定时与带宽估算
  - Lmax（burst_bytes_max）：单突发最大覆盖字节（granule size 上限），通常受 SRAM 窗口/总线/后端约束
  - row_window_bytes：行窗口的“有效子读字节之和”上限（不含空洞），用于在低活跃度下跨大 gap 合并
  - row_window_timeout_ns：窗口等待上限，超时立即封口；避免在低流量下无限等待造成饥饿
  - bank_bits/bank_shift：当为 0 时退化为仅 row；若提供需与 ramulator2 的 `AddrMapper` 对齐（当前默认关闭以避免误分桶）

8) 并发与背压
  - 下发行数受 `max_inflight_reads_` 限制；当达到上限时，`issueGranule_()` 直接返回，待后续任意下行响应回到时继续推进（GatherBufferIF.cc:234-241）
  - `tail_wait_timeout_ns`：EndGather 后的尾等待；当前记录 `gas_tail_wait_ns`，用于观察尾部返回拖尾（GatherBufferIF.cc:345-349）

9) 统计定义（已在 ELI 注册，可 CSV 可见）
  - `gas_unique_reads/bytes`：下行唯一合并读的笔数/覆盖字节总量（由 granule 计）
  - `gas_upstream_reads`：Gather 窗口内收到的上游 Read 数
  - `gas_gap_absorbed_bytes`：细合并吸收的空洞字节数（sum）
  - `gas_row_window_triggers/bytes`：行窗口触发次数/对应突发覆盖字节数（含空洞）
  - `gas_total_bursts`：实际发出的 granule/burst 笔数（便于直接计算平均突发长度）
  - `gas_total_payload_bytes`：burst 中有效负载字节（不含被吸收的空洞），用于计算“有效载荷比例”
  - `gas_inflight_peak`：采样的下行在途峰值
  - `gas_stage_cycles_*`：各阶段花费的周期数（窗口模式）
  - `gas_buffer_occupancy_bytes`：SRAM 回填时记录的占用字节（采样）

10) 上层对接（SnnPESubComponent 与 MultiCorePE）
  - SnnPESubComponent：
    - 接收 `CustomResp(GasStatData)` 并上卷到 MultiCorePE（`accumulateGasStats`），同时本地副本计入 `gas_unique_*_total`（SnnPESubComponent.cc:1315-1325）
    - 在 `gas_window_mode=1` 时不再逐周期发 Begin/End；由 GatherBufferIF 的窗口推进
  - MultiCorePE：
    - 注册 `gas_unique_reads_total/gas_unique_bytes_total` 并累计（MultiCorePE.cc:651-687，.h:160-161,302-303）
    - 提供窗口化统计 CSV（可选）；合并 `window_metrics.csv` 的 `buffer_max_bytes/inflight_peak` 到 `sb_peak_bytes/inflight_peak`

11) 退化/回退路径
  - `defer_issue_until_apply=0`：不进行延后构建；按 `merge_policy`（CL或Row）即时构建 granule 并发起下行
  - `gap_merge_enable=0` 或 `k==0 || Lmax==0`：自动禁用细合并，行为退化到行/CL 对齐的静态 granule
  - `row_window_enable=0` 或 bytes/timeout=0：禁用粗粒度合并；仅保留细合并
  - `bank_bits=0`：禁用 bank_row 分桶，退化为行分桶

12) 典型边界条件（已在自检覆盖或代码处理）
  - gap==k / new_len==Lmax：等于边界视为可吸收（细合并）；Lmax 以 new_len 判定
  - 组内重叠/相邻：`a<=cur_end` 直接拉伸 `cur_end` 并吸纳子读（不算空洞）
  - timeout 优先级：在尝试细合并失败后优先检查 timeout，再判断 bytes 触发，以减少等待抖动
  - 清理与一致性：Apply 发放/窗口切换时清空 `staging_reads_/required_set_/granules_`；行尾在 `doFlush_()` 清缓存

13) 复杂度与资源
  - 构建阶段复杂度：分桶 O(N)，组内排序 O(M log M)（M 为桶内读数量），线性扫描构段；整体近似 O(N log N)
  - 内存占用：
    - staging_reads_：Gather 窗口上游读的指针数组
    - sram_blocks_：granule 覆盖的段数据（以 key=(base,size) 为键）
    - granules_：granule 元信息 + 子读列表（用于 Apply 发放）

14) 例程伪代码（延后构建主路径）
 ```c++
// Gather: stage upstream reads
onRead(rd):
  if (stage==Gather && defer_issue_until_apply && gap_merge_enable) {
    staging_reads_.push_back(rd);
    staged_arrival_ns_[rd->id] = now_ns();
  } else { build_granule_immediate(rd); }

// Apply entry: build+sort+issue
maybeEnterApply_():
  if (stage==Gather && end_gather_seen_) {
    stage=Apply; if (defer_issue_until_apply) {
      groups = bucket_by_bank_row(staging_reads_);
      for (g in groups) {
        sort_by_addr(g);
        for (rd in g) {
          if (!has_segment) start_segment(rd);
          else if (overlap_or_adjacent(rd)) extend_segment(rd);
          else if (gap_ok_by_k_Lmax(rd)) extend_segment_mark_gap(rd);
          else if (timeout_exceeded(rd)) flush_segment(mark_rowwin=true), start_segment(rd);
          else if (bytes_ok_by_row_window(rd)) extend_segment_mark_rowwin(rd);
          else flush_segment(), start_segment(rd);
        }
        flush_segment(mark_rowwin=used_row_window);
      }
      sort_granules_by(sort_policy);
      for (gr in granules) issue_if_under_inflight_limit(gr);
    }
  }
```

## 5. Apply/Scatter 端到端语义（Phase‑1 实装）

- 端到端阶段事件（GatherBufferIF → SnnPESubComponent）：
  - `Begin/End Apply`：EndApply 需要 `inflight_down_==0` 才会发出，避免跨窗迟到响应污染下一窗；`stage_seq` 随窗口单调递增。
  - `Begin/End Scatter`：BeginScatter 时由内核按 `post` 升序应用累加、检查阈值并发放 spike；EndScatter 可触发 SRAM flush（按配置）。
- 内核端累加与发放：
  - Apply：在 Dense ReadResp 与 cache‑hit 路径对 `post_local` 调用 `accUpdate_()`（仅当 `apply_acc_enable=1` 且 `index_mode=post_row_pre_col`）。
  - Scatter：确定性顺序（`post` 升序）应用 delta → 调用 `checkAndFireSpike()` 进行阈值判断与发放。
- 可观测性：
  - 阶段事件 CSV：`seq,event,acc_updates,posts_touched,hwm_bytes,spill_records,spilled_bytes,spikes_emitted`
  - BeginScatter 前打印每窗口 Delta 摘要（日志）：acc_entries.size、HWM、updates、posts 等（快速肉眼确认是否累加到窗）。

参数与默认：
- `apply_acc_enable`：默认 0（关闭端到端累加/发放，对齐旧行为，需要时在脚本中开启）。
- `stage_events_csv`：可选输出文件路径（留空则不写）。

（测试辅助，默认关闭）
- `readresp_zero_fallback`：默认 0。仅在自检时打开，用于将 DRAM 返回的 0 映射为 `init_default_weight`（默认 0.5），以便快速观察到非零的 Apply 累加与 Spike 发放。正式实验请保持关闭。

## 9. 里程碑C：k 校准（gap_merge_k_bytes）

目标
- 通过短跑 sweep 自动标定细合并阈值 k，在不恶化平均时延的前提下，减少事务密度（reqs/MiB）或提升 avg_burst_bytes。

方法（数据驱动，默认行窗口关闭）
- 工具：`sst_dram_si/tools/k_calibrate.py`（新增）
- 步骤：
  1) 固定 `sort_policy` 与 `burst_bytes_max`，关闭行窗口（`row_window_enable=0`）；
  2) 扫描 k ∈ {0, 512, 1024, 2048, 4096, 8192}（可修改）；
  3) 每个 k 运行 100us 或 2ms，派生 `avg_burst_bytes, reqs_per_mib, avg_read_latency_0`；
  4) 以 `reqs_per_mib` 最小且 `avg_read_latency_0` 不高于基准（k=0）+δ 的 k 为 `k_recommended`；
  5) 输出 `summary_k_<dur>.csv` 与 `k_recommended_<dur>.json`，并回填脚本默认值（可选）。

备注
- 若需更“物理”的 k：可引入微基准对比“合并 vs 拆分”在不同 gap 下的总时间，近似反解 `k ≈ (tRA+tCA+tPRE)*B`。当前以数据驱动的 sweep 作为默认实现，便于快速稳定落地。

### 8+. k 定标（当前默认与复现）

- 当前默认：`gap_merge_k_bytes = 2048`（2 KiB）。来自 C1 数据驱动 sweep（100us/2ms）推荐；在 2ms 下验证优于 k=0（reqs/MiB 更低，avg_read_latency_0 稳定）。
- 微基准（C2）注意：在 row_hit 场景下，bench 会给出 `k=0`（gap=0 即满足合并更优），不适合作为工程默认；如使用 k_from_bench 回填，请加 `--min_bytes`（建议 ≥1024）或采用 row_switch 场景做稳健下界。
- 复现：
  - Sweep：`python3 sst_dram_si/tools/k_calibrate.py --dur 100us` 与 `--dur 2ms`
  - Bench：
    - `./sst sst_dram_si/test_kcal_bench.py`

### 9+. 自适应控制（Phase‑1，闭环在线调参）

目标
- 在 `window_auto=1` 的窗口边界执行“探测→评估→采纳/回退”，在线自适应合并参数，稳健降低 `reqs_per_mib`，同时保持延迟与背压健康。

范围（Phase‑1，已落地）
- 调参维度：`k(gap_merge_k_bytes)`、`row_window_bytes`、`row_window_timeout_ns`（`sort_policy` 暂不纳入闭环，仅在 bank_row 自动对齐可靠时手动启用）。
- 触发点：EndScatter 之后、下一窗口 BeginGather 之前（已在 `GatherBufferIF::clockTick()` 的窗口状态机里接线）。
- 默认：关闭（`ctrl_enable=0`）；开启后只影响 GAS 前端合并/行窗口，不改动上层语义与统计口径。

窗口指标（内部聚合，按窗计算）
- `win_payload_bytes`/`win_bursts` → `avg_burst_bytes = payload/bursts`
- 段级延迟的均值（ns）：按 granule issue→回包时间累计（与 C3 的段计时复用）
- `win_inflight_peak`：窗口内下行在途峰值（背压代理）
- `pseudo_row_adj_rate`：按下发顺序，邻接 granule 映射到同一 row（或 bank_row） 的比例（行局部性代理）

控制策略（爬山 + 迟滞）
- 每 `ctrl_probe_every_N` 个窗口，在单一维度上选择“邻居候选”（来自候选列表），探测 1 个窗口；满足以下任一才采纳：
  - `reqs_per_mib` 相对改善 ≥ `ctrl_eps_reqs`（默认 2%），且延迟不恶化（`avg_seg_latency_ns ≤ 上次 + ctrl_lat_tol_ns`，默认 1ns）
  - 或 `avg_burst_bytes` 相对提升 ≥ `ctrl_eps_burst`（默认 5%），且延迟不恶化
- 采纳后进入 `ctrl_cooldown_N` 个窗口冷却；回退则恢复旧配置并同样冷却。维度按 `k → rowwin_bytes → timeout` 轮换。

参数与默认（脚本已透传）
- `ctrl_enable`(0/1), `ctrl_probe_every_N`(4), `ctrl_cooldown_N`(4), `ctrl_eps_reqs`(0.02), `ctrl_eps_burst`(0.05), `ctrl_lat_tol_ns`(1)
- 候选列表：`ctrl_k_list`("512,1024,2048,4096,8192"), `ctrl_rowwin_list`("0,16384,32768,65536"), `ctrl_timeout_list`("0,300,600")
- 仅窗口模式有效；只在窗口边界改参，保证 in‑flight 已清空。

实现要点（代码锚点）
- GatherBufferIF 窗口状态机：`sst_workspace/sst-elements/src/sst/elements/SnnDL/GatherBufferIF.cc`（EndScatter→`controlStep_()`）

统计与观测
- 新增统计（ELI Accumulator）：`gas_ctrl_probes`、`gas_ctrl_adopts`、`gas_ctrl_reverts`（每发生一次 +1）。
- 轨迹（建议）：可在后续添加 `gas_ctrl_trajectory_csv`（每窗输出 window_seq、k、row_window_bytes、timeout、公制）。当前可结合窗口级派生与 stdout 验证。

使用建议

## 7. 统计口径与派生指标

- 基线（方案1）：
  - 总读字节：`multicore_pe_0,mem_req_size_bytes.Sum.u64`（CSV）
  - 事务/时延/行命中：从 ramulator2 日志解析（`num_read_reqs_0`、`avg_read_latency_0`、`row_*`）

- GAS（方案2）：
  - 总读字节/笔数：`gas_unique_bytes_total`、`gas_unique_reads_total`
  - 行窗口贡献：`gas_row_window_triggers`、`gas_row_window_bytes`
  - 直方图：`gas_req_coalesce_size_bytes`（平均突发长度可由总读字节/笔数获得）
  - 活跃度 f（新增）：
    - 定义：窗口内活跃 pre 轴数 / 列宽（`weights_cols`）。由 `SnnPESubComponent` 在读取路径收集活跃列（post_row_pre_col/BCSR），在 GAS 阶段事件处做窗口滚动；
    - 聚合统计：`gas_activity_f`（PE 级 Accumulator）；
    - 窗口化 CSV：追加列 `avg_activity_f`（窗口内 f 均值），输出路径由 `window_csv` 指定（脚本默认 `sst_dram_si/stats/windowed/windows_20us.csv`）。

- 派生指标（比较建议）：
  - `total_read_MiB = total_bytes / 1024^2`
  - `reqs_per_MiB = num_read_reqs_0 / total_read_MiB`
  - `avg_burst_bytes = gas_unique_bytes_total / gas_unique_reads_total`
  - `row_window_share = gas_row_window_bytes / gas_unique_bytes_total`
  - 行命中率：`row_hits / (row_hits+row_misses+row_conflicts)`

## 5. NoC 接入（P1 → P1‑2）

- P0：最小可用基线（Spike-only，本地 DRAM），参考 `sst_dram_si/test_noc_timestep.py`，输出 NIC/路由器计数与（已启用）SnnNIC `msg_latency_ns` 直方图。
- P1‑1：SnnNIC 导出脉冲轨迹（`export_spike_csv`）到 `analysis/spikes.csv`，便于 NoC 重放。
- P1‑2：NoC 轻量轨迹驱动与分解工具：
  - `sst_dram_si/tools/noc_trace_driver.py`：读取 `granules.csv + spikes.csv (+stage_events.csv)`，支持 `--multicast=replicate|tree`，输出 `analysis/noc_trace_summary_*.csv`（含 `injected_flits/edge_flits/avg/p95/p99`）。4×4 mesh 脚本 `test_mesh_4x4.py` 现将多节点 granule/窗口峰值落盘至 `analysis/granules_mesh.csv`、`analysis/window_metrics_mesh.csv`，并将脉冲轨迹写入 `analysis/spikes_mesh.csv`，可直接用于重放。
  - `sst_dram_si/tools/derive_end2end_breakdown.py`：融合 `stage_events(sim_time_ns)` + NoC 汇总 + `granules.csv` 输出 `analysis/end2end_breakdown.csv`，口径 `t_total = t_DRAM_wait + t_NoC + t_compute`。

运行示例：
```bash
./sst sst_dram_si/test_dram_si_single_pe.py
python3 sst_dram_si/tools/noc_trace_driver.py \
  --granules sst_dram_si/analysis/granules.csv \
  --spikes analysis/spikes.csv \
  --stages sst_dram_si/stats/stage_events_db_100us.csv \
  --bw 32GiB/s --multicast tree \
  --out sst_dram_si/analysis/noc_trace_summary_tree.csv

python3 sst_dram_si/tools/derive_end2end_breakdown.py \
  --stages sst_dram_si/stats/stage_events_db_100us.csv \
  --noc sst_dram_si/analysis/noc_trace_summary_tree.csv \
  --granules sst_dram_si/analysis/granules.csv \
 --out sst_dram_si/analysis/end2end_breakdown.csv
```

注意：`test_noc_timestep.py/test_mesh_4x4.py` 中已为 SnnNIC 传入 `export_spike_csv`，默认落在 `analysis/spikes.csv`，可直接用于重放。
